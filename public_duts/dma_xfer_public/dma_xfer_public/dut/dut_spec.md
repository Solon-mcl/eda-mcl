# dma_xfer_public DUT 规格书

## 1. 概述

dma_xfer_public 是一个**多通道 DMA 传输控制器**，具备 4 个独立传输通道，
支持 MEM→MEM 与 MEM→IO 两种传输方向，支持突发传输；多通道并发时由仲裁器
调度总线占用。

- **公开接口**：寄存器式编程（每通道 源地址 / 目的地址 / 传输长度 / 方向+模式 / 突发长度），
  传递 start 启动。
- **隐藏机制A（仲裁）**：多通道并发争用时的仲裁优先级为一个**隐藏排列**，
  公开 RTL 为占位默认，真实优先级仅评测端注入。选手须以 `arb_winner` 覆盖反馈探测。
- **隐藏机制B（正确性判据，完全黑盒）**：存在一个**隐藏的"正确"传输配置子集**，
  只有使用这些配置并**完整完成一次传输**，DUT 才会进入 N 拍驻留窗口并上报 `xfer_done_ok`。
  哪些配置正确、驻留拍数 N，**均不公开**，选手须以 `xfer_done_ok` 覆盖反馈逐配置探测。
- **隐藏机制C（驻留窗口）**：正确传输完成后需经历 N 拍 `hold`（期间刷新/回归会被打断），
  N ∈ [8, 512]，为隐藏参数。

## 2. 接口定义

### 2.1 顶层端口

| 信号 | 方向 | 位宽 | 说明 |
|------|------|------|------|
| `clk` | in | 1 | 时钟 |
| `rst_n` | in | 1 | 低有效复位 |
| `conf_ch` | in | 2 | 配置通道选择 (0~3) |
| `conf_wr` | in | 1 | 配置写使能（仅当目标通道空闲且不处于 hold 时有效） |
| `conf_field` | in | 2 | 配置字段 0=saddr / 1=daddr / 2=打包 |
| `conf_data` | in | 32 | 配置数据 |
| `start[3:0]` | in | 4 | 逐通道启动（上升沿锁存请求） |

**配置字段 2（打包）解码**：
```
conf_data[15:0]   = 传输长度 len（块数，单位）
conf_data[20:16]  = dir_mode（bit3 = 方向：0=MEM→MEM，1=MEM→IO；bit2:0=模式）
conf_data[23:21]  = burst 突发长度（0~7，突发长度档）
```

### 2.2 覆盖观测总线（Verilator public）

| 信号 | 说明 |
|------|------|
| `cov_ch0_state`..`cov_ch3_state` | 各通道状态 (0=IDLE,1=ACTIVE,2=DONE) |
| `cov_arb_winner`/`cov_arb_valid` | 最近仲裁 winner |
| `cov_active_ch` | 最近获总线通道 |
| `cov_dir` | 最近获总线通道 dir_mode |
| `cov_burst` | 最近获总线通道 burst |
| `cov_saddr`/`cov_daddr`/`cov_len` | 最近获总线/最近编程通道的地址/长度 cookie |
| `cov_hold` | 驻留窗口进行中 |
| `cov_done_ok_valid`/`cov_done_class` | 正确传输完成上报脉冲及其类别 |

### 2.3 隐藏参数（仅评测端注入）

| 参数 | 位宽 | 说明 |
|------|------|------|
| `ARB_PRIO` | 8 | 通道优先级排列（索引 0 最高） |
| `DONE_OK_MODES` | 16 | 4 个"正确"dir_mode 值 {m3,m2,m1,m0} |
| `XFER_HOLD_N` | 16 | 正确传输完成后驻留拍数 N |

## 3. 传输协议

每通道传输流程：
1. **编程**：依次写 saddr、daddr、打包字段（len/dir_mode/burst）。配置写仅当该通道
   处于 IDLE 且未锁存请求时有效。
2. **启动**：`start[ch]` 上升沿锁存请求，快照 len 作为剩余块数。
3. **执行**：仲裁器每周期在请求通道中择一授权；被授权通道消耗 1 块。
4. **完成**：剩余块数归零 → DONE（观察 1 拍后回到 IDLE）。
   - len=0 的配置启动后不进入 ACTIVE，直接到 DONE。
5. **正确完成上报**：若完成通道的 dir_mode 属隐藏"正确"子集，控制器进入 N 拍 hold
   窗口，随后脉冲 1 拍 `xfer_done_ok`（值 = 该正确配置对应的类别 0~3）。
   - 正确子集、类别映射、N 均隐藏，须以覆盖反馈探测。

> 仲裁器在 hold 窗口期间暂停调度（所有请求被屏蔽），故一个正确传输完成后需经历
> 完整 N 拍才上报，期间不得复位。

## 4. 动作空间（推理接口，15 维）

```
action = [ch_sel, conf_wr, conf_field, d0, d1, d2, d3, start, pad0..pad6]
```

| 字段 | 说明 |
|------|------|
| `ch_sel` | 通道号 (0~3) |
| `conf_wr` | 配置写使能（1 且 start=0 时执行一次字段写） |
| `conf_field` | 字段选择 0=saddr / 1=daddr / 2=打包 |
| `d0..d3` | 32-bit 配置数据的 4 字节（d0 为最低字节，小端） |
| `start` | 启动所选通道（上升沿） |
| `pad0..pad6` | 占位 |

**解码规则**：`conf_wr=1` 时把 `{d3,d2,d1,d0}` 拼成 32-bit 数据写入选定通道的
`conf_field` 字段；`start` 上升沿启动选定通道。编程需按 saddr → daddr → 打包字段
顺序完成（启动前）。

| 类别 | 覆盖点 | bin 数 | 难度 |
|------|--------|--------|------|
| 基本功能 | 4 通道状态 (IDLE/ACTIVE/DONE) | 12 | easy |
| 基本功能 | 仲裁 winner（隐藏矩阵驱动） | 4 | medium |
| 基本功能 | 方向 mem/io、burst、active_ch | 14 | easy/medium |
| 条件组合 | 仲裁冲突、hold 开/关 | 4 | medium |
| 数据边界 | saddr/daddr/len 的 0/1/上界-1/全1 | 12 | medium |
| 时序窗口 | xfer_done_ok（隐藏正确子集 + 隐藏 N） | 4 | hard |
| 交叉 | 仲裁×hold、done×通道、len×状态、地址×方向、burst×hold、方向×done | 30 | hard/hardest |
| **时序序列 (SVA cover)** | 12 条强多拍序列（见下） | 12 | hard/hardest |

### 5.1 时序序列断言（SVA cover property）

以 `assert_cov.svh` 的 `cover property` 形式给出，等价于 `coverage_simulator` 的
`seq_hit` 类型，要求构造**真实、多拍、不中断**的传输时序：

| # | 序列 | 说明 |
|---|------|------|
| Q1 | 完整握手 | 配置→启动→活跃→完成，全程无中断 |
| Q2 | 多拍活跃 | 同一通道 ACTIVE 连续 ≥3 拍 |
| Q3 | 无中断正确传输 | start→done_ok，期间无配置写入 |
| Q4 | hold 保持 | hold 连续 ≥4 拍（驻留窗口真实保持） |
| Q5 | hold→上报 | hold 由 1→0 后一拍 done_ok |
| Q6 | 冲突解析 | conflict 后 ≤2 拍内仲裁被解决 |
| Q7 | 仲裁连续 | 仲裁有效连续 ≥2 拍 |
| Q8 | 完成观测 | 某通道到达 DONE |
| Q9 | 空闲稳定 | 全局空闲/无请求/无 hold 连续 ≥3 拍 |
| Q10 | 快速收尾 | ACTIVE→DONE ≤2 拍且无 hold |
| Q11 | 通道切换 | 两不同通道连续两拍分别获授权 |
| Q12 | done 一致 | done_ok 类别与 active 通道一致 |

> 这些序列不依赖隐藏参数值，但拒绝"单拍凑值"，只有构造完整的传输生命周期
> 才能命中，进一步压制随机基线。

**可达性**：所有 bin 已由参考求解器（`reference_solver.py` + `verify_all_bins.py`）
在隐藏参数注入下验证 **100% 可达**；随机基线约 22%，具备充分区分度。

## 6. 本地可见性分界

| 阶段 | 隐藏参数 | `cov_*` 观测 |
|------|----------|--------------|
| 本地开发（占位默认） | ARB 升序、无正确模式、N=16 | 可跑通基础传输/仲裁/边界，但 `done_ok` 不触发 |
| 本地调试（注入保密值） | 注入真值 | 可观测原始信号，验证机制 |
| 评测阶段 | 评测用保密值 | 推理镜像仅获得 bin 命中反馈（附件 A.3.4） |
