# 通用时序宏规划器（v2）

## 目标

在不知道 DUT 名称、内部实现和隐藏覆盖点的前提下，让通用策略从单周期字段扫描扩展到多周期事务探索。本版本没有读取、运行或针对验证集 DUT 编写规则；开发证据仅来自人工合成协议测试和三个公开 DUT 回归。

## 方法

语义 IR 将动作字段归为寄存器写读、推进、事件、故障、使能、恢复、复位和保留位。规划器据此动态构造四类与具体协议无关的宏：

- `configure`：遍历规范中声明的合法寄存器地址与边界数据，并在存在读接口时回读；
- `control`：逐个脉冲推进、事件、故障、使能、读和恢复控制，避免把互不相关的控制同时置位；
- `temporal`：组合配置、空闲等待、事件脉冲和持续推进，系统扫描 1、2、4、8、16、32 周期；
- `recovery`：先积累事件或故障状态，再执行规范可见的恢复/复位并开始新 episode。

所有动作都经过语义 IR 的范围裁剪，保留位固定为零，寄存器地址优先使用规范解析出的地址集合。

宏调度采用轻量 UCB：以“新增覆盖 bin / 消耗周期”为收益，在探索与复用高收益宏之间平衡；覆盖长期停滞时额外提升 `temporal` 和 `recovery`，用于触达计数阈值、超时、故障累计和恢复序列等单周期随机动作难以覆盖的状态。学习仅保存在本次推理状态中，不更新模型权重。

## 验证结果

合成协议测试覆盖以下约束：合法地址、字段范围、保留位清零、寄存器写读、推进/事件/故障脉冲、恢复复位，以及调度器对奖励宏的重新选择。

公开 DUT 的 30k Verilator 固定回归：

| DUT | 覆盖结果 |
|---|---:|
| dma_xfer_public | 92/92（100%） |
| spi_master_public | 120/120（100%） |
| spi_xfer_public | 86/86（100%） |

原始结果保存在 `results/generic_temporal_public_30k.json`。公开 DUT 仍走原有专家策略，这组回归用于确认通用路径改造没有造成行为回退。

## 局限

该方法只能使用规范显式呈现的字段语义；若文档没有描述某个控制信号、寄存器或时间尺度，规划器无法可靠推断其隐藏含义。UCB 的即时覆盖收益也可能低估“前置配置很长、最终才产生覆盖”的宏，后续可引入跨宏信用分配和约束关系图改善这一点。
