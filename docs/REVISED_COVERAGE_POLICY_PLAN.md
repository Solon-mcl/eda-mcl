# 覆盖率驱动通用激励：审查结论与修订实施规划

> 后续已取得两篇论文 PDF，并形成含论文审查的新报告：`PAPER_INFORMED_ALGORITHM_AND_EXECUTION_PLAN.md`。本文件保留原审查过程记录，论文相关结论请以新报告为准。

## 0. 依据与边界

本规划依据 `guide/赛题原文.txt`、现有 `UNIVERSAL_POLICY_ALGORITHM_AND_TRAINING_PLAN.md`、仓库代码及已有实验记录。微信链接 [文章一](https://mp.weixin.qq.com/s/9yd3bsj1wnxxju95EARm9w)、[文章二](https://mp.weixin.qq.com/s/uNGJ3Dqcawp0XvZNFl_3-g)在本环境触发访问验证；Jina Reader 连接超时，**未取得论文标题、正文或实验数据**。因此本文没有把两篇文章的任何具体方法或效果当作已验证事实。取得原文后按第 7 节的证据表补充，不以猜测代替引用。

赛题文件是需求与接口依据，不是指示我们必须采用 RL、进化算法或 LLM。赛题评测输入只有 spec、covergroup 路径，以及逐周期累计二值覆盖向量、步数和预算；不存在状态寄存器、中间派生信号或 RTL 的评测期可见性保证。`coverage_meta.json` 在题面中出现，但构造函数只传两个路径，必须验证其实际挂载位置；找不到时从 covergroup 建立保守 bin 映射，映射不能确认时退化为总量反馈。

评分按三个隐藏 DUT 的终值覆盖率和 1000-cycle 采样 AUC 计算，权重分别为 0.6、0.4。单 DUT 约 5 万至 10 万 cycles，全流程墙钟不超过 2 小时；`predict()` 建议小于 30 ms。评测期不得更新模型权重，但可以更新搜索统计、执行队列和规划状态。LLM 每 DUT 最多 50 万输入输出 Token，API 耗时计入总墙钟。

## 1. 对现有规划的审查

| 原方案 | 判断 | 修订 |
|---|---|---|
| Semantic IR、目标 bin 身份、合法性约束、宏动作队列 | 保留。这些是跨 DUT 的必要基础。 | 把 IR 与执行器做成可重放、可审计的接口；未知语义必须显式标注。 |
| 四类 option + UCB | 可作基线，不能承担长事务生成。当前门禁后的本地 30k 结果在 SPI master 为 5/120，SPI xfer 为 2/86。 | 扩展为可组合的事务模板库，加有期限的参数搜索和目标相关的宏选择。 |
| 立即训练 0.5–2M 参数程序解码器 | 暂缓。5108 条记录中仅 10 条正收益、四类分布 `[5,0,0,5]`，不足以学习复杂的条件程序。 | 先生成高质量、可重放、跨结构的数据，再训练候选排序器；解码器须通过增益门禁才加入提交版。 |
| IQL/离线 actor-critic | 暂缓。仅凭稀疏且有强选择偏差的教师轨迹，反事实价值估计难以可靠。 | 先用监督排序/上下文 bandit 评估；仅在数据支持和留出测试上证实增益后增加离线 RL。 |
| 按 DUT 名称禁用任何专家 | 目标合理，但不应因此放弃通用事务原语。 | 禁用名称路由和针对隐藏 DUT 的脚本；允许按 spec 结构实例化同一套通用原语。 |
| 每 option 500 正样本、公开集 100% 等硬门槛 | 数字缺少样本独立性与可达性依据。 | 以结构家族留出、置信区间和实际分数增益定门槛；100% 为冲刺目标，不是模型是否有效的唯一条件。 |
| 难度加权 `reward/cycle` | 可用于启发式，但与官方计分不完全一致；稀有 bin 权重也不一定等于得分权重。 | 主要优化新增 bin 的时间位置、终值和官方采样 AUC；难度权重只作并列目标或探索先验。 |

**证据口径：** `docs/GENERALIZATION_EVAL.md` 曾记录旧专家方案在本仓库三个公开 DUT 30k/Verilator 达到 100%；现有通用门禁方案明显退化。这些是不同版本/实验记录，需用同一代码快照和同一后端重新比较。更重要的是，赛题原文列出的公开 DUT 是 AES、SPI 主设备、温控，而本仓库为 DMA、SPI master、SPI xfer。仓库结果不能冒充赛题官方公开集成绩。先核对官方发布包与本地包版本。

## 2. 推荐架构：结构化规划 + 在线黑盒搜索 + 可选模型

```text
spec + covergroup (+ 可用的 metadata)
  → 严格解析的字段/约束/目标 IR
  → 候选目标与可执行事务模板
  → 预算感知调度器：早期扫易 bin，随后攻缺失 bin
  → 参数搜索：边界/枚举/组合/时间窗口/重置
  → 合法性检查与动作队列 → predict() 每周期弹出一个 float32 向量
                 ↑
       新增 bin 集合、停滞时长、成功/失败历史
```

事务原语包括：`reset/recover`、`configure/readback`、`pulse/start`、`hold/advance`、`ordered sequence`、`fault/retry`。每个原语记录前置条件、保持条件、终止条件、周期上限、参数域以及可能影响的 bin。程序是原语组合，不把整条 DUT 专用脚本作为学习单元。结果正确性 bin 要先寻找可完成的功能事务，再做输出相关参数搜索；不可从 bin 名称臆造隐藏判据。

调度器以目标 bin 或小目标簇为单位建账，保存候选程序、参数区间、尝试次数、实际耗费 cycles、命中 bin、最后尝试时间。早期用低成本边界和枚举扫描增加 AUC；长期窗口、cross、结果正确性目标尽早启动，避免最后才发现所需周期不够。每个模板设置最短执行长度和超时，不因中间无新增覆盖就提前 reset。长时序采用几何递增窗口、边界邻域细扫与模式交叉，成功后局部最短化并重放确认。反馈仅有覆盖位，所以“失败”只表示本次程序未新增 bin，不能推断内部哪一拍失败。

选程序时用有界探索：估计`新增未覆盖 bin 数 / (执行周期 + 规划开销)`，加不确定性与长期未尝试目标的探索项；对跨程序前置步骤采用**重放/删除实验确认信用**，不要固定向前三步乘 `0.5^distance` 就当作因果。所有在线更新都是统计与队列，不改变训练权重。

## 3. LLM 的具体位置

LLM 适合做低频语义编译器，不适合每周期吐动作。初始化时把 spec、covergroup 的相关片段及可用 metadata 交给赛题允许的模型，要求输出带来源引用的结构化 JSON：字段角色与合法范围、reset 极性、事务前置关系、可能的 bin→事务关联、未知或冲突项、候选程序骨架。只接受能由原文片段和本地解析器验证的条目；无法验证的内容降权为探索假设。LLM 不应声称知道隐藏窗口长度、温区阈值或内部状态。

可选第二次调用仅在明显停滞的宏边界触发：输入压缩的缺失 bin、试过的程序摘要、参数区间和剩余预算，请模型提出**新的可检验假设及试验顺序**。同一失败摘要只调用一次，设置每 DUT 调用数、Token、请求时限和总墙钟的硬上限；API 无响应、超配额、结构校验失败则继续本地策略。两种模式都要做完整消融：无 LLM、仅初始化、初始化加停滞重规划。只有在未见结构和官方风格包上稳定提高覆盖 AUC/终值且不造成超时，才默认启用。

现有 `deepseek_planner.py` 已有初始化单次调用和失败降级，但当前 JSON 输出是原始动作向量，验证主要检查维度、数值有限和长度，未证明时序依赖、字段范围或 `float32` 精度合法。下一版应改为**语义程序 + 来源位置 + 约束证明/未知项**，统一走 IR 编译器；删除 `family_hint` 作为决策依据。当前提交证据 `LLM_REPORT.md` 声明未使用 LLM，若最终启用必须同步更新模型版本、端点、调用次数、Token、延迟和消融结果。

## 4. 训练路线与决策门禁

**第一阶段：先把无需训练的强基线做好。** 固定运行器、随机种子、官方采样 AUC 算法；复现纯随机、简单贪心、当前通用、旧专家和修订模板策略。以同一代码版本、同一 DUT/后端、同一预算评估。公开 DUT 的历史 100% 用于定位退化，不作为隐藏泛化证据。

**第二阶段：构造可信数据。** 从教师轨迹和模板搜索中提取成功与失败的完整事务，保存 IR、起始覆盖 mask、目标、程序、周期、逐 bin 增量、重放结果、采样概率与代码版本。用删除/缩短重放检验程序关键步骤。合成 DUT 必须有可执行状态机和独立覆盖实现；训练/测试按结构模板与依赖图分割，不能只靠名称或字段哈希防泄漏。不同合成变体共享模板时必须归为同一 split。先做少量真正不同结构的模板并确认能提升留出结果，再决定是否扩到千例。

**第三阶段：轻量学习。** 首选模型对`(目标、IR、程序候选、历史)`排序或预测成功率/成本；候选仍由合法模板编译器生成。采用监督对比/排序损失和校准，在线调度保留探索。只有排序器在多种留出结构、至少 3 个随机种子、相同墙钟和周期预算下，稳定优于无模型策略，才加载提交版。若出现足够多样的可重放正例，再试程序解码器；离线 RL 作为后续实验，而非关键路径。

**第四阶段：版本门禁。** 每次替换提交候选，必须同时满足：接口与合法性测试通过；P99 `predict()` 在评测级 CPU 上有余量；在公开包不显著退化；结构家族留出上终值与 AUC 的配对置信区间不劣；API 故障时仍完成全程。不要以训练准确率、单次 100% 或某一验证 DUT 的手工修复替代这些条件。

## 5. 工程核对项

1. **输入契约：** 运行时只依赖两个构造路径；旁路 `coverage_meta.json` 先探测存在性，再校验 bin 数和顺序。`coverage_state` 是累计二值，程序结果用前后 mask 的集合差计算。
2. **动作精度：** action 是 `float32`。整数超过 `2^24` 时未必能精确表达；如某 DUT 要求精确高位 key/token，必须核对适配层映射是否拆字段或有编码。否则单靠数值钳制仍会产生不可达激励，需按官方解码规范处理。
3. **覆盖实现：** 本地 Verilator + CoverageSimulator 与云端 VCS 可能有采样/时序边界差异。对关键 sequence/cross 写小规模双实现对照；未获得 VCS 时至少保存逐周期信号与期望 bin 触发条件。
4. **时间预算：** 分别测 `__init__`、API、P50/P99 `predict()`、仿真交互和总 3 DUT 墙钟。题面一处称初始化可较长，另一处规定全流程 2 小时；按**初始化也计入 2 小时**设计更稳妥。
5. **可重复性：** 报告每个 DUT 至少 3 个独立种子、每 1000 cycles 曲线、均值及离散度、终值、AUC、未命中 bin 类型、超时率和 API 用量。消融至少覆盖模板/目标调度、时间窗口搜索、LLM 三个关键因素。

## 6. 实施顺序与交付判据

| 里程碑 | 交付物 | 完成判据 |

| M0 官方包核对 | DUT 清单、接口/metadata/动作映射差异表 | 解释本仓库与赛题原文 DUT 不一致，并能在原样官方包上启动。 |
| M1 测评基座 | 统一 runner、AUC/墙钟统计、逐 bin 诊断 | 相同快照可复现基线；三种预算和至少三种子。 |
| M2 模板搜索 | 通用事务编译器、长期窗口/组合搜索、恢复逻辑 | 本地公开集较当前通用策略的终值和 AUC 同时改善，长程序可重放。 |
| M3 LLM 实验 | 结构化语义编译、停滞重规划、验证/降级 | 无 LLM 对照和同预算消融证实净增益，否则保持关闭。 |

| M5 提交 | 镜像、覆盖/消融/LLM 报告、README | 标准接口、无在线权重更新、API 失败降级、全流程墙钟检查通过。 |

## 7. 对两篇论文的待补证据

取得正文后逐篇记录：标题/作者/年份/原始论文链接；DUT 类型与是否跨设计；动作粒度；可见状态与覆盖反馈；奖励和预算；训练/推理是否需要 RTL、波形或内部寄存器；与 CRT/随机/贪心的同预算比较；可迁移到本题的具体模块及其先决条件。尤其检验论文是否依赖本题评测端不可见的中间状态，或是否只在单一处理器 DUT 上验证。没有这些信息，不给论文方法分配实现优先级。

## 8. 最终建议

先交付**无外部依赖、可跨 DUT 组合的结构化搜索策略**，把当前在 SPI 上的明显退化补回；再把 LLM 作为受约束的语义解析和停滞时假设生成器，以同预算消融决定是否启用；模型训练优先做候选排序，程序生成与离线 RL 留到数据质量和留出增益足以支撑时。最终取舍由隐藏参数/结构留出、AUC、终值、墙钟共同决定，而不是由算法类别或模型大小决定。
