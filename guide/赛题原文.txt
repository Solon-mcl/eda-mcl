一、赛题名称
基于AI的覆盖率驱动通用测试激励自动生成
二、命题单位
湖南泛联新安信息科技有限公司
三、赛题背景
功能验证是芯片设计流程中耗时最长的环节之一，其中测试激励的生成质量直接影响验证效率和覆盖率达到收敛的速度。当前业界主流
方法依赖工程师手动编写定向测试或使用受约束随机测试（CRT），存在以下痛点：
手动编写激励效率低，难以覆盖边界情况；
随机测试存在大量冗余激励，在复杂设计上覆盖率收敛缓慢；
缺乏自适应的反馈机制，无法根据已覆盖情况动态调整激励策略；
针对特定设计优化的激励生成方法难以迁移到不同类型的被测设计。
近年来，强化学习、进化算法、大语言模型等AI技术在芯片设计领域展现出强大能力，为激励自动生成提供了新的思路：将DUT视为环
境，激励作为动作序列，覆盖率作为奖励信号，通过与DUT交互自主学习高效的激励策略，加速覆盖率收敛。
本题要求参赛者设计并实现一种自动激励生成方法，在组委会提供的多种不同类型被测设计（DUT）上，以覆盖率为优化目标，在给定
的仿真预算内达到尽可能高的覆盖率。

四、赛题描述
4.1 目标
设计并实现一套自动测试激励生成系统，以覆盖率指标为核心反馈信号，在多个不同类型的DUT上自动生成高质量仿真激励序列。方法
应具备跨DUT的泛化能力，在覆盖率收敛效率和最终覆盖率上显著优于随机基线方法。

4.3.2 覆盖率定义与采集
核心原则：开发和评测阶段使用相同的覆盖点定义，确保策略学习的有效性和一致性。覆盖组（covergroup）是一组覆盖点
（coverpoint）和交叉覆盖点（cross）的集合，覆盖点再细分为一个个 bin（如操作码分类值）。每个覆盖点的 bin 命中状态构成覆盖率
反馈向量。覆盖点、覆盖组、bin 等术语的完整定义及格式规范详见附件 A。
开发/验证阶段（参赛者本地）：
组委会提供覆盖率模拟工具（Coverage Simulator），一个 Python 工具包
该工具读取覆盖点定义，在 Verilator 仿真过程中观测 DUT 信号，按覆盖组规则计算各覆盖点的命中状态，输出与评测阶段一致的
numpy 向量格式
工具实现详见附件 C
评测阶段（组委会云端）：
使用商用仿真器（VCS）的 SystemVerilog covergroup 原生采集功能覆盖率（含基本覆盖点、交叉覆盖点等）
每个 DUT 配套  covergroup.svh  定义文件，覆盖点总 bin 数：26~120 个（含交叉覆盖点），按难度分层
每步仿真后返回标准覆盖率反馈（格式见附件A）
为什么分两阶段：
开发阶段用 Verilator + 模拟工具：免费、快速、可本地运行
评测阶段用 VCS：覆盖组采集结果权威、与工业界一致
两阶段覆盖定义相同，仅采集实现不同——组委会在赛前完成双工具交叉验证
Docker 镜像提交规范和推理接口标准详见附件 B

class InferenceInterface:
    def __init__(self, dut_spec_path: str, covergroup_path: str):
        """接收DUT规格说明和覆盖组定义文件路径"""
    def predict(self, coverage_state: np.ndarray,
                step: int, max_steps: int) -> np.ndarray:
        """根据当前覆盖率状态返回下一个激励动作
        Args:
            coverage_state: 当前各覆盖点已覆盖状态（二值向量，shape=(N,), dtype=float32）
            step:           当前仿真步数（0-indexed）
            max_steps:      最大仿真步数
        Returns:
            action: 下一个激励动作，一维 numpy 向量（shape=(D,), dtype=float32）
                    D 为动作空间维度，由 DUT spec 定义
                    评测脚本中的仿真适配层负责将 action 解码为 DUT 引脚激励
        """
评测约束：
 predict()  内部不得修改模型权重参数；允许根据覆盖率反馈动态调整prompt策略或Agent规划
可以读取  coverage_state 、 step  等输入信息进行推理决策
action 向量的维度 D 由 DUT spec 定义，可理解为动作向量中独立控制通道的数量。对于多参数激励（如操作码 + 多个操作数），
所有参数展开为一维向量，解码规则见 DUT spec

动作空间缩减策略建议：
实际 DUT 的激励空间通常远大于示例，直接使用全空间离散 RL 会出现稀疏奖励问题
建议采用以下一种或多种策略缩减动作空间：
分层生成：先选择激励类型（事务类型），再在受限范围内选择参数
语义约束：基于 DUT spec 过滤非法组合，缩减有效动作范围
LLM 辅助：利用 LLM 解析 spec 中的语义信息，生成合理操作数或事务参数
连续参数化：对操作数维度使用连续动作空间 + 离散化

第二部分 附件 A：覆盖组定义规范
A.1 概述
每个 DUT 配套一个覆盖组定义文件  covergroup.svh ，定义功能覆盖率（functional coverage）的采样点——包括基本覆盖点
（coverpoint）和交叉覆盖点（cross）。覆盖组使用 SystemVerilog 语法编写，评测阶段通过商用仿真器（VCS）编译和采样，开发/验
证阶段通过组委会提供的覆盖率模拟工具（参见附件 C）在 Verilator 侧输出相同格式的覆盖率反馈。
开发和评测使用相同的覆盖点定义，仅采集实现方式不同。
A.2 通用规范
1. 采样时机：所有覆盖点统一使用  @(posedge clk)  采样
2. 覆盖点类型：每个 DUT 的覆盖组包含以下五类覆盖点：
基本功能覆盖点
数据边界覆盖点
条件组合覆盖点
时序窗口覆盖点（ sequential ，用于"需持续保持/完整时序才能达成"的功能窗口）
多变量交叉覆盖点
3. 覆盖点总数：26~120 个（含交叉覆盖点）

A.3 覆盖点类型定义
A.3.1 基本功能覆盖点
覆盖 DUT 的基本操作模式、状态值或功能编码。
opcode: coverpoint instr[6:0];

A.3.2 数据边界覆盖点
覆盖数据通路的边界值、特殊值。
data_val: coverpoint data_out {
    bins zero   = {0};
    bins max    = {32'hFFFF_FFFF};
    bins small  = {[1:15]};
}
A.3.3 条件组合覆盖点
覆盖控制路径的分支条件取值组合。
branch_taken: coverpoint branch_taken_signal;
A.3.4 时序窗口覆盖点（sequential）
覆盖"需持续保持、完整时序序列达成"的功能窗口，绑定时序达成/结果正确性等派生信号，
命中的前提是 Agent 构造出持续正确的激励序列。该类覆盖点
通常配合  coverage_meta.json  里  type: "sequential" 。评测端统一按"仅上报 bin 是否命中"
掩码，不向 Agent 泄漏触发该 bin 的中间派生信号原始值。
win_mode: coverpoint win_mode {       // 完整窗口按 mode 达成
    bins mode0 = {2'd0};
    bins mode1 = {2'd1};
}
win_len:  coverpoint win_len {        // 窗口长度档（具体值保密）
    bins len0 = {2'd0};
    bins len1 = {2'd1};
}
注： win_mode / win_len  等派生信号属于评测机制内部信号，只在仿真/覆盖采集侧存在，
不应写入  dut_spec.md 。

import numpy as np
class InferenceInterface:
    """推理接口——由评测脚本调用"""
    def __init__(self, dut_spec_path: str, covergroup_path: str):
        """
        初始化推理环境。
        Args:
            dut_spec_path:   DUT 功能规格说明文件路径 (Markdown)
            covergroup_path: 覆盖组定义文件路径 (SystemVerilog)
        """
        pass
    def predict(
        self,
        coverage_state: np.ndarray,
        step: int,
        max_steps: int,
    ) -> np.ndarray:
        """
        根据当前覆盖率状态，返回下一个激励动作。
        Args:
            coverage_state: 当前各覆盖点已覆盖状态 (shape=(N,), dtype=float32)
                            1.0 表示已覆盖，0.0 表示未覆盖
            step:           当前步数（0-indexed）
            max_steps:      最大仿真步数
        Returns:
            action: 下一个激励动作，一维 numpy 向量 (shape=(D,), dtype=float32)
                    D 为动作空间维度，由 DUT spec 定义
                    评测脚本中的仿真适配层负责将 action 解码为 DUT 引脚激励
        """
        raise NotImplementedError
约束：
 predict()  单次调用耗时建议 ≤ 30ms（评测环境 CPU 上）。该值与 2 小时墙钟上限、3 个评测 DUT、每 DUT 5 万 cycles 的约束
对应：2h ÷ 3 ÷ 5 万 ≈ 44ms/cycle，扣除 VCS 仿真开销后留给 predict 的预算约 30ms。超时不影响评分但会减少可完成的 cycles
数，从而影响最终覆盖率
评测脚本在单线程中循环调用  predict() ，不并发
 __init__()  允许较长的初始化时间（如加载模型权重），不计入评测时间
严格禁止在  predict()  中修改模型权重参数；允许在推理时根据覆盖率反馈动态调整prompt策略或Agent规划（prompt
engineering层面的适应性调整）。不得更新模型权重
激励解码约定
组委会评测脚本负责将  predict()  返回的 action 向量解码为 DUT 引脚激励（参赛者无需实现解码逻辑）：
1.  predict()  返回一个 numpy 向量（ np.ndarray ，shape=(A,), dtype=float32），A 为动作空间维度
2. 每个 DUT 的  dut_spec.md  定义了从 action 向量到 DUT 引脚信号的映射规则
3. 评测脚本根据  dut_spec.md  的映射表，将 action 向量转换为仿真器输入信号
4. 解码规则随基础镜像一同提供，包含在评测脚本的仿真适配层中

from coverage_simulator import CoverageSimulator
import verilator_binding  # Verilator C++ 到 Python 的绑定

cov_sim = CoverageSimulator("dut/coverage_meta.json")
state = cov_sim.reset()
# 仿真循环
for cycle in range(max_cycles):
    # 1. 生成激励（参赛者算法）
    action = agent.predict(state, cycle, max_cycles)
    # 2. 应用到 DUT
    verilator_binding.apply_stimulus(action)
    # 3. 读取 DUT 信号值
    signals = verilator_binding.read_signals(['instr', 'alu_result', 'carry', ...])
    # 4. 更新覆盖率（用模拟工具替代 VCS covergroup）
    state = cov_sim.step(signals)
    # 5. 计算奖励
    reward = cov_sim.coverage - prev_coverage

C.6 覆盖点格式说明
non-cross 覆盖点（basic / boundary / condition / sequential）：
 signal : DUT 中可观测的信号名， [M:N]  表示位选（如  alu_result[31]  表示符号位）。对于 condition 类型，signal 也可以是逻辑
组合后的派生信号名（如  carry_overflow  表示  {carry_flag, overflow_flag}  的组合值），派生信号不在 DUT 顶层直接存在，参赛
者需在仿真循环中显式计算并注入到  signal_values  字典中。对于  sequential  类型，其  signal  为窗口达成/结果正确性等派生信
号（如  win_mode / win_len / win_ctl ），由仿真模型派生，采集侧同样只上报"bin 是否命中"。
 bins[].match : 两种模式——整数表示信号精确相等匹配；字符串 "x == 0"  /  "x != 0"  表示边界条件匹配（CoverageSimulator 内
置支持这两种表达式，不解析通用布尔表达式）
 difficulty （可选）：覆盖点难度标签（easy/medium/hard/hardest），由 CoverageSimulator 忽略，供参赛者参考
 num_bins （可选）：覆盖点 bin 数量，与  bins[]  数组长度一致
cross 覆盖点：
 parents : 引用父覆盖点名称列表（必须与  coverpoints  中已定义的覆盖点名称一致）
 cross_bins[].combinations : 父覆盖点 bin 索引的组合列表，每个组合为  [bin_idx_p0, bin_idx_p1, ...] ，对应  parents  数组的
顺序
